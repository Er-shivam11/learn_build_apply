
# GIL (Global Interpreter Lock)

## 1. Definition (30 sec Interview Answer)

> **The Global Interpreter Lock (GIL) is a mutex in CPython that allows only one thread to execute Python bytecode at a time within a single process. It simplifies memory management by protecting Python objects from concurrent access, but it prevents true parallel execution of CPU-bound Python threads.**

# 3. Why was GIL introduced?

Imagine Python objects.

```python
salary = 50000
```

Suppose two threads try to update it simultaneously.

```text
Thread A

salary += 1000
```

and

```text
Thread B

salary += 5000
```

Both read

```text
50000
```

at the same time.

Possible result

```text
51000

or

55000

or corrupted data
```

This is called a **Race Condition**.

---

Without GIL

```text
Thread A

↓

salary = 50000

──────────────

Thread B

↓

salary = 50000
```

Both modify simultaneously.

Unsafe.

---

With GIL

```text
Thread A

↓

Gets Lock

↓

Updates Salary

↓

Releases Lock

↓

Thread B

↓

Gets Lock

↓

Updates Salary
```

Safe.


# 9. When is GIL released?

Generally during blocking I/O operations such as:

* Reading files
* Network requests
* Database queries
* Sleeping (`time.sleep()`)

This allows another thread to acquire the GIL and continue executing Python bytecode.

---

# 10. Interview Summary

| Scenario        | Best Choice     | Why                                                                                                                  |
| --------------- | --------------- | -------------------------------------------------------------------------------------------------------------------- |
| CPU-bound tasks | Multiprocessing | Each process has its own Python interpreter and its own GIL, allowing true parallel execution on multiple CPU cores. |
| I/O-bound tasks | Multithreading  | Threads spend much of their time waiting for I/O, and the GIL is released during those waits, improving throughput.  |

---

## 30-Second Interview Answer

> **The GIL (Global Interpreter Lock) is a mutex in CPython that ensures only one thread executes Python bytecode at a time within a process. It simplifies memory management and prevents race conditions on Python objects. Because of the GIL, multithreading is effective for I/O-bound tasks, where threads frequently wait and release the GIL, but it doesn't provide true parallelism for CPU-bound tasks. For CPU-intensive workloads, multiprocessing is preferred because each process has its own interpreter and its own GIL.**
