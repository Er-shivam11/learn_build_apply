
# Garbage Collection (GC)

## Definition

> **Garbage Collection (GC) is Python's automatic memory cleanup mechanism that removes objects that are no longer in use. In CPython, memory is managed primarily through reference counting, while the garbage collector detects and cleans up circular references that reference counting alone cannot free.**

---

## One-Line Analogy

> **Imagine a hotel: when no guest is using a room, housekeeping automatically cleans it so it can be reused.**

---

# Real-Life Example (E-commerce)

```python
class Order:

    def __init__(self, order_id):
        self.order_id = order_id


order = Order(101)

print("Order Created")

del order

print("Order Deleted")
```

### Output

```text
Order Created
Order Deleted
```

# Reference Counting Example

```python
import sys

order = []

print(sys.getrefcount(order))

another = order

print(sys.getrefcount(order))
```

### Possible Output

```text
2
3
```

*(The exact numbers may vary because `getrefcount()` temporarily adds one reference.)*

# Circular Reference Example

```python
class Customer:
    pass


class Order:
    pass


customer = Customer()
order = Order()

customer.order = order
order.customer = customer

del customer
del order

print("Circular reference created")
```

Python's **Garbage Collector** will detect and clean this cycle because reference counting alone cannot.

---

# What Happens Internally?

```text
Object Created
        ↓
Reference Count = 1
        ↓
More References
        ↓
Reference Count Increases
        ↓
References Removed
        ↓
Reference Count = 0
        ↓
Memory Released

-----------------------------

Circular Reference
        ↓
Reference Count Never Becomes 0
        ↓
Garbage Collector Detects Cycle
        ↓
Memory Released
```

# Why Garbage Collection is Needed?

Reference counting works well for most objects.

But consider this:

```text
Customer
    │
    ▼
Order

▲      │
│      ▼

Customer
```

Even if you remove external references,

```python
del customer
del order
```

both objects still reference each other.

Reference count never reaches **0**.

That's why Python's **Garbage Collector** exists.

---

# Advantages

* ✅ Automatic memory cleanup
* ✅ Prevents most memory leaks
* ✅ Handles circular references
* ✅ Developers rarely free memory manually

---

# Drawbacks

* ❌ Small runtime overhead
* ❌ Garbage collection may pause execution briefly
* ❌ Large object graphs can take longer to scan

---

# Common Interview Questions

### Q1. What is Garbage Collection?

> Python's automatic mechanism for reclaiming unused memory.

---

### Q2. What is Reference Counting?

> A technique where each object tracks how many references point to it. When the count becomes zero, the object is immediately deallocated.

---

### Q3. Why is Garbage Collection needed if Python has reference counting?

> Because reference counting cannot detect and free **circular references**.

---

### Q4. Which module controls Garbage Collection?

```python
import gc
```

---

### Q5. Can Garbage Collection be disabled?

Yes.

```python
gc.disable()
```

Enable again:

```python
gc.enable()
```

---

# ⭐ Interview Answer (30 Seconds)

> **"In CPython, memory management primarily relies on reference counting, where an object is deallocated as soon as its reference count reaches zero. However, reference counting cannot handle circular references, so Python also includes a garbage collector that periodically detects and removes cyclic objects. Together, these mechanisms provide automatic memory management."**
