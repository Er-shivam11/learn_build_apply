# Mutable vs Immutable

## Definition

> **Mutable objects can be modified after they are created without changing their identity, whereas immutable objects cannot be modified. Any modification to an immutable object creates a new object with a new identity.**

---

## One-Line Analogy

> **A whiteboard is mutable—you can erase and write on the same board. A printed book is immutable—you can't change its contents; you need a new edition.**

---

# Real-Life Example (E-commerce)

**Scenario:** An order's item list can change, but the order ID cannot.

```python
order_id = 101
items = ["Laptop", "Mouse"]

print(id(order_id))
print(id(items))

order_id += 1
items.append("Keyboard")

print(order_id)
print(items)

print(id(order_id))
print(id(items))
```

### Output

```text
140718353951920
140718354330112

102
['Laptop', 'Mouse', 'Keyboard']

140718353951952
140718354330112
```

*(IDs will differ on your machine.)*

# What Happens Internally?

## Immutable (`int`)

```text
order_id = 101

Stack
───────
order_id
    │
    ▼

Heap
───────
101
```

After

```python
order_id += 1
```

Python creates a **new object**.

```text
Stack
───────
order_id
    │
    ▼

Heap
───────
102
```

The old `101` object is no longer referenced.

---

## Mutable (`list`)

```python
items = ["Laptop", "Mouse"]
```

```text
Stack
───────
items
   │
   ▼

Heap
────────────────────
["Laptop", "Mouse"]
```

After

```python
items.append("Keyboard")
```

Python modifies the **same object**.

```text
Stack
───────
items
   │
   ▼

Heap
──────────────────────────────────
["Laptop", "Mouse", "Keyboard"]
```

The object's identity (`id`) remains the same.

# Why Does It Matter?

Example:

```python
items1 = ["Laptop", "Mouse"]
items2 = items1

items2.append("Keyboard")

print(items1)
```

Output

```text
['Laptop', 'Mouse', 'Keyboard']
```

Both variables point to the **same object**.

---

Immutable example:

```python
a = 100
b = a

b += 1

print(a)
print(b)
```

Output

```text
100
101
```

Because integers are immutable, `b` points to a **new object**.

---

# Advantages

### Mutable

* ✅ Easy to update
* ✅ Memory efficient for frequent changes
* ✅ Best for collections

---

### Immutable

* ✅ Thread-safe
* ✅ Hashable (can be dictionary keys)
* ✅ Prevents accidental modification
* ✅ More predictable

---

# Drawbacks

### Mutable

* ❌ Can be modified unexpectedly
* ❌ Shared references may cause bugs

---

### Immutable

* ❌ Every modification creates a new object
* ❌ Slightly less efficient for frequent updates

---

# Common Interview Questions

### Q1. What is mutable?

> An object whose contents can be changed without creating a new object.

---

### Q2. What is immutable?

> An object that cannot be changed after creation; modifying it creates a new object.

---

### Q3. Why can a list be modified but a tuple cannot?

> Lists are mutable, while tuples are immutable by design.

---

### Q4. Why can tuples be dictionary keys but lists cannot?

> Because tuples are immutable and hashable; lists are mutable and therefore not hashable.

---

### Q5. How can you verify mutability?

Use `id()`:

```python
print(id(obj))
```

If the `id` changes after modification, a new object was created (immutable). If it stays the same, the object was modified in place (mutable).

---

# ⭐ Interview Answer (30 Seconds)

> **"Mutable objects can be modified after creation without changing their identity, while immutable objects cannot be modified; any update creates a new object. Lists, dictionaries, and sets are mutable, whereas integers, strings, and tuples are immutable. This distinction is important for memory management, object sharing, and thread safety."**

# List vs Tuple vs Set vs Dictionary

## Definition

> **List, Tuple, Set, and Dictionary are Python's four primary built-in collection data structures. They differ in mutability, ordering, uniqueness, indexing, and use cases. Choosing the appropriate data structure improves performance, readability, and correctness.**

---

## One-Line Analogy

> **Think of an e-commerce system:**
>
> * **List** → Shopping Cart (ordered, editable)
> * **Tuple** → Order ID (fixed, cannot change)
> * **Set** → Unique Coupon Codes (no duplicates)
> * **Dictionary** → Customer Database (key-value information)

---

# 1. List (Shopping Cart)

## Real-Life Example

```python
cart = ["Laptop", "Mouse"]

cart.append("Keyboard")

print(cart)
```

### Output

```text
['Laptop', 'Mouse', 'Keyboard']
```

### Features

* Ordered ✅
* Mutable ✅
* Duplicates Allowed ✅
* Indexed ✅

---

# 2. Tuple (Order ID)

## Real-Life Example

```python
order = (101, "Shivam", "Laptop")

print(order)
```

### Output

```text
(101, 'Shivam', 'Laptop')
```

### Features

* Ordered ✅
* Immutable ✅
* Duplicates Allowed ✅
* Indexed ✅

---

# 3. Set (Coupon Codes)

## Real-Life Example

```python
coupons = {"SAVE10", "NEWUSER", "SAVE10"}

print(coupons)
```

### Output

```text
{'SAVE10', 'NEWUSER'}
```

### Features

* Ordered ❌
* Mutable ✅
* Duplicates ❌
* Indexed ❌

---

# 4. Dictionary (Customer Details)

## Real-Life Example

```python
customer = {
    "name": "Shivam",
    "city": "Mumbai"
}

print(customer)
```

### Output

```text
{'name': 'Shivam', 'city': 'Mumbai'}
```

### Features

* Ordered ✅ *(Python 3.7+)*
* Mutable ✅
* Duplicate Keys ❌
* Key-Value Pair ✅

---

# Comparison Table

| Feature    | List          | Tuple      | Set          | Dictionary       |
| ---------- | ------------- | ---------- | ------------ | ---------------- |
| Ordered    | ✅             | ✅          | ❌            | ✅                |
| Mutable    | ✅             | ❌          | ✅            | ✅                |
| Indexed    | ✅             | ✅          | ❌            | By Key           |
| Duplicates | ✅             | ✅          | ❌            | Keys ❌, Values ✅ |
| Syntax     | `[]`          | `()`       | `{}`         | `{key:value}`    |
| Use Case   | Shopping Cart | Fixed Data | Unique Items | Lookup Data      |

---

# When to Use?

### List

Use when:

* Order matters
* Data changes frequently
* Duplicates are allowed

Example:

```python
cart = ["Laptop", "Mouse"]
```

---

### Tuple

Use when:

* Data should never change
* Hashable values are needed
* Returning multiple values

Example:

```python
location = (19.0760, 72.8777)
```

---

### Set

Use when:

* Only unique values are needed
* Fast membership testing
* Removing duplicates

Example:

```python
skills = {"Python", "SQL", "Python"}
```

---

### Dictionary

Use when:

* Fast lookup by key
* Mapping related data
* JSON-like structures

Example:

```python
employee = {
    "id": 101,
    "name": "Shivam"
}
```

---

---

---

### Dictionary

# Common Interview Questions

### Q1. List vs Tuple?

> **Lists are mutable; tuples are immutable.**

---

### Q2. Set vs List?

> **Sets store only unique values and are not indexed, whereas lists allow duplicates and preserve order.**

---

### Q3. Why use a Tuple?

> **When data should remain constant and be hashable.**

---

### Q4. Why use a Set?

> **For uniqueness and fast membership testing.**

---

### Q5. Why use a Dictionary?

> **For efficient key-value storage and retrieval.**

---

# ⭐ Interview Answer (30 Seconds)

> **"Python provides four primary collection types. Lists are ordered and mutable, making them suitable for dynamic collections. Tuples are ordered but immutable, making them ideal for fixed data. Sets store unique values and provide fast membership testing. Dictionaries store key-value pairs and offer efficient lookups by key. The choice depends on whether ordering, mutability, uniqueness, or key-based access is required."**
