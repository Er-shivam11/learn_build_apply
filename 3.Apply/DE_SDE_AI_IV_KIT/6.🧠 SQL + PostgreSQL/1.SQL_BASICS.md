# 1. RDBMS vs NoSQL

## Definition

**RDBMS stores structured data in related tables using a fixed schema and SQL. NoSQL stores semi-structured or unstructured data with flexible schemas, often using JSON-like documents.**

## Why

* Maintain relationships between data.
* Ensure consistency with constraints and transactions.
* Scale differently depending on workload.

## Analogy

* **RDBMS:** An Excel workbook with multiple linked sheets.
* **NoSQL:** A Google Drive folder where every file can have a different structure.

## Syntax

RDBMS

```sql
CREATE TABLE customers (
    customer_id INT,
    name VARCHAR(100)
);
```

NoSQL (Document)

```json
{
  "customer_id": 1,
  "name": "Shivam",
  "skills": ["Python", "SQL"]
}
```

## Fully Commented Example

```sql
-- RDBMS stores data in rows and columns.

CREATE TABLE customers (

    customer_id INT PRIMARY KEY,      -- Unique customer id

    name VARCHAR(100),                -- Customer name

    city VARCHAR(50)                  -- Customer city

);
```

## Execution

```
Database
    ↓
Schema
    ↓
Table
    ↓
Rows
    ↓
Columns
```

## Quick Revision

* RDBMS → Structured Data
* SQL Language
* Fixed Schema
* Relationships
* ACID Transactions

NoSQL

* Flexible Schema
* JSON Documents
* Horizontal Scaling
* High Availability

# 2. Tables & Schemas

## Definition

**A table stores rows and columns. A schema is a logical container that organizes tables, views, indexes, and functions.**

## Why

Schemas help organize large databases into logical modules.

## Analogy

```
Database
   ↓
School

Schema
   ↓
Classroom

Table
   ↓
Attendance Register
```

## Syntax

```sql
CREATE SCHEMA ecommerce;

CREATE TABLE ecommerce.customers (

    customer_id INT PRIMARY KEY,

    name VARCHAR(100),

    city VARCHAR(50)

);
```

## Fully Commented SQL

```sql
CREATE SCHEMA ecommerce;             -- Logical Folder

CREATE TABLE ecommerce.customers (   -- Schema.Table

    customer_id INT PRIMARY KEY,

    name VARCHAR(100),

    city VARCHAR(50)

);
```

## Execution

```
Database
     ↓
Schema
     ↓
Table
     ↓
Rows
```

## Quick Revision

* Database contains Schemas.
* Schema contains Tables.
* Tables contain Rows and Columns.

# 3. CRUD

## Definition

CRUD represents the four basic database operations:

* Create
* Read
* Update
* Delete

## Why

Every application performs CRUD operations on its database.

## Analogy

Instagram

* Upload Post → Create
* View Feed → Read
* Edit Caption → Update
* Delete Post → Delete

## Syntax

```sql
INSERT INTO customers VALUES (1,'Shivam','Mumbai');

SELECT * FROM customers;

UPDATE customers
SET city='Pune'
WHERE customer_id=1;

DELETE FROM customers
WHERE customer_id=1;
```

## Fully Commented SQL

```sql
-- CREATE

INSERT INTO customers

VALUES

(1,'Shivam','Mumbai');

------------------------------------------------

-- READ

SELECT *

FROM customers;

------------------------------------------------

-- UPDATE

UPDATE customers

SET city='Pune'

WHERE customer_id=1;

------------------------------------------------

-- DELETE

DELETE

FROM customers

WHERE customer_id=1;
```

## Execution

```
Application
      ↓
SQL Query
      ↓
Database
      ↓
Rows Modified
```

## Quick Revision

* INSERT → Create
* SELECT → Read
* UPDATE → Modify
* DELETE → Remove

# 4. Constraints

## Definition

Constraints enforce rules to maintain data integrity and consistency.

## Why

Without constraints, duplicate, invalid, or inconsistent data could be stored.

## Analogy

Exam Registration Form

* Roll Number → Unique
* Name → Mandatory
* Age → Must be ≥18

## Syntax

```sql
CREATE TABLE customers(

    customer_id INT PRIMARY KEY,

    email VARCHAR(100) UNIQUE,

    name VARCHAR(100) NOT NULL,

    age INT CHECK(age>=18),

    city VARCHAR(50)

);
```

## Fully Commented SQL

```sql
customer_id INT PRIMARY KEY      -- Unique + Not Null

email VARCHAR(100) UNIQUE        -- No duplicates

name VARCHAR(100) NOT NULL       -- Mandatory

age INT CHECK(age>=18)           -- Validation

city VARCHAR(50)
```

## Quick Revision

* PRIMARY KEY
* FOREIGN KEY
* UNIQUE
* NOT NULL
* CHECK
* DEFAULT

# 6. WHERE

Filters rows before returning them.

```sql
SELECT *

FROM customers

WHERE city='Mumbai';
```

---

# 7. ORDER BY

Sorts query results.

```sql
SELECT *

FROM customers

ORDER BY name ASC;
```

---

# 8. DISTINCT

Removes duplicate values.

```sql
SELECT DISTINCT city

FROM customers;
```

---

# 9. Aggregate Functions

Perform calculations across multiple rows.

```sql
SELECT

COUNT(*) AS total_customers,

SUM(amount) AS total_sales,

AVG(amount) AS average_sales,

MIN(amount) AS minimum_sale,

MAX(amount) AS maximum_sale

FROM orders;
```

---

# 10. GROUP BY

Groups rows before applying aggregate functions.

```sql
SELECT

city,

COUNT(*) AS total_customers

FROM customers

GROUP BY city;
```

---

# 11. HAVING

Filters groups after aggregation.

```sql
SELECT

city,

COUNT(*) AS total_customers

FROM customers

GROUP BY city

HAVING COUNT(*) > 5;
```

---

# 12. CASE WHEN

Implements conditional logic.

```sql
SELECT

customer_id,

amount,

CASE

    WHEN amount>=10000 THEN 'Premium'

    WHEN amount>=5000 THEN 'Gold'

    ELSE 'Regular'

END AS customer_type

FROM orders;
```

---

# 13. NULL Handling

NULL represents an unknown or missing value.

```sql
SELECT *

FROM customers

WHERE city IS NULL;
```

Using COALESCE:

```sql
SELECT

name,

COALESCE(city,'Unknown')

FROM customers;
```
