# Phase 4 — Database Internals

Writing SQL is only half the job.

A Senior Engineer should also understand **how the database executes queries**, **how transactions work**, and **why one query is faster than another**.

---

# 26. Transactions

## Definition

A **Transaction** is a group of one or more SQL operations executed as a single logical unit. Either **all operations succeed (COMMIT)** or **all are undone (ROLLBACK)**.

---

## Why

Imagine transferring ₹1000 from one bank account to another.

If money is deducted but not credited due to a server crash, the data becomes inconsistent.

Transactions prevent such issues.

---

## Analogy

ATM Cash Withdrawal

```
Verify Card
     ↓
Verify PIN
     ↓
Deduct Money
     ↓
Dispense Cash
     ↓
Update Balance

If any step fails
↓

Everything is cancelled.
```

---

## Syntax

```sql
BEGIN;

UPDATE accounts
SET balance = balance - 1000
WHERE account_id = 1;

UPDATE accounts
SET balance = balance + 1000
WHERE account_id = 2;

COMMIT;
```

Rollback Example

```sql
BEGIN;

UPDATE products
SET stock = stock - 1
WHERE product_id = 101;

ROLLBACK;
```

---

## Fully Commented SQL

```sql
BEGIN;                                      -- Start Transaction

UPDATE accounts

SET balance = balance - 1000                -- Debit Sender

WHERE account_id = 1;

UPDATE accounts

SET balance = balance + 1000                -- Credit Receiver

WHERE account_id = 2;

COMMIT;                                     -- Save Permanently
```

---

## Execution

```
BEGIN
   ↓
SQL 1
   ↓
SQL 2
   ↓
SQL 3
   ↓
COMMIT

OR

ROLLBACK
```

---

## Drawbacks

* Long transactions hold locks.
* Can block other users.
* Increase chances of deadlocks.

---

## Quick Revision

* BEGIN
* COMMIT
* ROLLBACK
* Atomic Unit

# 27. ACID Properties

## Definition

ACID ensures transactions remain reliable even during failures.

---

## Why

Without ACID

Money can disappear.

Orders can duplicate.

Inventory becomes incorrect.

---

## Analogy

Online Movie Ticket Booking

```
Seat Selected
↓

Payment

↓

Ticket Generated

↓

Seat Reserved

Everything succeeds

OR

Everything fails
```

---

## ACID

### A — Atomicity

All or Nothing.

---

### C — Consistency

Database remains valid before and after transaction.

---

### I — Isolation

Multiple users should not interfere with each other.

---

### D — Durability

Once committed,

data survives crashes.

---

↓

# 28. Locks

## Definition

Locks prevent multiple users from modifying the same data simultaneously.

---

## Why

Imagine two customers buying the last laptop.

Without locking,

both orders may succeed.

---

## Analogy

Library Book

Only one student can borrow the same physical book at a time.

---

## Common Locks

* Shared Lock (Read)
* Exclusive Lock (Write)

---

## Example

```sql
BEGIN;

SELECT *

FROM products

WHERE product_id = 101

FOR UPDATE;
```

---

## Execution

```
User A

Locks Row

↓

User B

Waits

↓

User A

COMMIT

↓

User B Continues
```

---

## Drawbacks

* Blocking
* Waiting
* Deadlocks

---

## Quick Revision

Shared Lock

↓

Read

---

Exclusive Lock

↓

Write

# 29. Indexing

## Definition

An **Index** is a special data structure that speeds up data retrieval without scanning the entire table.

---

## Why

Without an index,

the database checks every row.

With an index,

it jumps directly to the required location.

---

## Analogy

Book Index

Instead of reading 1000 pages,

open the index,

go directly to page 450.

---

## Syntax

```sql
CREATE INDEX idx_customer

ON orders(customer_id);
```

---

## Execution

Without Index

```
Row1

↓

Row2

↓

Row3

↓

...

↓

Target
```

With Index

```
Index

↓

Target
```

---

## Drawbacks

* Uses disk space.
* Slows INSERT/UPDATE/DELETE because indexes must also be updated.

---

## Quick Revision

* Faster SELECT
* Slower INSERT
* Extra Storage

---

# 30. Query Optimization

## Definition

Query Optimization is the process of executing SQL in the fastest and most efficient way.

---

## Why

Bad SQL can take minutes.

Optimized SQL can take milliseconds.

---

## Analogy

Google Maps

Many routes exist.

Choose the shortest one.

---

## Example

Bad

```sql
SELECT *

FROM orders;
```

Better

```sql
SELECT customer_id,

amount

FROM orders

WHERE customer_id = 1;
```

---

## Optimization Tips

* Select only required columns.
* Use indexes.
* Filter early.
* Avoid unnecessary DISTINCT.
* Avoid SELECT * in production.

---

## Drawbacks

Requires understanding execution plans and data distribution.

---

---

## Why

---

GPS Route Preview

---

## Common Terms

* Nested Loop

---

## Drawbacks

Reading execution plans requires practice.

# 32. Cardinality

## Definition

Cardinality represents the number of unique values in a column.

---

## Why

The optimizer uses cardinality to choose the best execution plan.

---

## Analogy

Employee IDs

High Cardinality

Every employee has a different ID.

Gender

Low Cardinality

Only Male/Female/Other.

---

## Example

```

2

3

4

5

High

----------------

Gender

M

F

M

F

Low
```

---

## Drawbacks

Incorrect estimates can produce poor execution plans.

---

## Quick Revision

# 33. Statistics

## Definition

Statistics are metadata collected by PostgreSQL about table contents and data distribution.

---

## Why

The optimizer relies on statistics to estimate query cost.

---

## Analogy

Traffic Information

Google Maps uses traffic statistics to choose the fastest route.

---

## PostgreSQL

```
ANALYZE orders;
```

Updates statistics.

---

## Execution

```
Table

↓

Statistics

↓

Optimizer

↓

Best Plan
```

---

## Drawbacks

Outdated statistics can cause slow queries and poor execution plans.

---

## Quick Revision

Statistics

↓

Optimizer Decisions

---

↓

Keep Statistics Fresh
