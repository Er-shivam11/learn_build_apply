# Definition

> **Inheritance represents an "is-a" relationship where a child class inherits behavior from a parent class. Composition represents a "has-a" relationship where one class contains another class as an attribute. Composition is generally preferred because it provides loose coupling and better flexibility.**

---

# One-Line Analogy

### Inheritance

> **Car is a Vehicle**

```text
Car IS-A Vehicle
```

---

### Composition

> **Car HAS-A Engine**

```text
Car HAS-A Engine
```

---

# Inheritance Example

## E-commerce

```python
class Payment:

    def pay(self):
        print("Payment Processed")


class CreditCardPayment(Payment):
    pass


payment = CreditCardPayment()

payment.pay()
```

### Output

```text
Payment Processed
```

---

# Flow

```text
CreditCardPayment

↓

↓
```

# Composition Example

## E-commerce

```python
class Engine:

    def start(self):
        print("Engine Started")


class Car:

    def __init__(self):
        self.engine = Engine()

    def drive(self):
        self.engine.start()
        print("Car Moving")


car = Car()

car.drive()
```

### Output

```text
Engine Started
Car Moving
```

---

# Flow

```text
Car

↓

Engine Object

↓

start()

↓

Car Moving
```

# Real Project Example

### Inheritance

```python
class User:
    pass

class Customer(User):
    pass

class Admin(User):
    pass
```

Relationship:

```text
Customer IS-A User

Admin IS-A User
```

---

### Composition

```python
class Address:
    pass

class Customer:

    def __init__(self):
        self.address = Address()
```

Relationship:

```text
Customer HAS-A Address
```

---

# Comparison

| Feature                        | Inheritance  | Composition  |
| ------------------------------ | ------------ | ------------ |
| Relationship                   | IS-A         | HAS-A        |
| Coupling                       | Tight        | Loose        |
| Flexibility                    | Lower        | Higher       |
| Reuse                          | Parent Class | Object Reuse |
| Changes in Parent Affect Child | Yes          | No           |
| Preferred in Modern Design     | Less         | More         |

---

# Why Composition is Preferred?

Suppose:

```python
class Engine:
    pass
```

Tomorrow:

```python
class ElectricMotor:
    pass
```

Only change:

```python
self.engine = ElectricMotor()
```

Car still works.

With inheritance, redesign may be required.

---

# Advantages of Inheritance

* ✅ Code reuse
* ✅ Polymorphism
* ✅ Cleaner hierarchy

---

# Drawbacks of Inheritance

* ❌ Tight coupling
* ❌ Fragile base class problem
* ❌ Harder maintenance

---

# Advantages of Composition

* ✅ Flexible
* ✅ Loose coupling
* ✅ Easier testing
* ✅ Easier maintenance
* ✅ Preferred in SOLID design

---

# Drawbacks of Composition

* ❌ More objects
* ❌ Slightly more code

---

# Common Interview Questions

### Q1. What is Inheritance?

> Child class acquires properties and methods of a parent class.

---

### Q2. What is Composition?

> A class contains another class as an object.

---

### Q3. Which is preferred?

> **Composition over Inheritance** is generally preferred.

---

### Q4. Why?

> Because composition provides loose coupling, flexibility, and maintainability.

---

### Q5. Real-world example?

Inheritance:

```text
Admin IS-A User
```

Composition:

```text
Order HAS-A Payment
Customer HAS-A Address
Car HAS-A Engine
```

---

# ⭐ Interview Answer (30 Seconds)

> **"Inheritance models an IS-A relationship where a child class extends a parent class. Composition models a HAS-A relationship where a class contains other objects to achieve functionality. While inheritance provides code reuse and polymorphism, composition offers better flexibility, loose coupling, and maintainability. Therefore, modern software design generally favors composition over inheritance."**
