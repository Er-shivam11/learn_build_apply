# `super()`

## Definition (30 Seconds)

> **`super()` is a built-in Python function used to call methods or constructors of the parent class. It avoids explicitly naming the parent class and follows the Method Resolution Order (MRO), making inheritance cleaner, more maintainable, and especially useful in multiple inheritance.**

---

## One-Line Analogy

> **Think of `super()` as forwarding a customer request to the next department in the company's predefined workflow (MRO) instead of directly calling a specific department.**

---

# Real-Life Example (E-commerce)

**Scenario:** When an order is created, the parent class initializes common order details, and the child class adds payment details.

```python
class Order:

    def __init__(self):
        print("Order Created")


class Payment(Order):

    def __init__(self):
        super().__init__()
        print("Payment Completed")


payment = Payment()
```

### Output

```text
Order Created
Payment Completed
```

---

# Execution Flow

```text
Payment()

        ↓

Payment.__init__()

        ↓

super().__init__()

        ↓

Order.__init__()

        ↓

Order Created

        ↓

Back to Payment.__init__()

        ↓

Payment Completed
```

---

# Why Not Call the Parent Directly?

You could write:

```python
Order.__init__(self)
```

But this is **not recommended** because:

* It tightly couples the child to a specific parent.
* If the parent class changes, you must update every child.
* It breaks cooperative multiple inheritance.

Using `super()` is cleaner:

```python
super().__init__()
```

---

# Multiple Inheritance Example

```python
class A:

    def show(self):
        print("A")


class B(A):

    def show(self):
        print("B")
        super().show()


class C(B):

    def show(self):
        print("C")
        super().show()


obj = C()
obj.show()

print(C.mro())
```

### Output

```text
C
B
A

[<class '__main__.C'>,
 <class '__main__.B'>,
 <class '__main__.A'>,
 <class 'object'>]
```

Notice that `super()` **does not mean "call my parent"**.

It means:

> **"Call the next class according to the MRO."**

---

# Why `super()` Uses MRO

Suppose:

```python
class Order(Payment, Discount):
```

The MRO is:

```text
Order
   ↓
Payment
   ↓
Discount
   ↓
object
```

If `Payment` calls:

```python
super().process()
```

Python goes to the **next class in the MRO**, which is `Discount`, **not necessarily the direct parent you might expect**.

This is why `super()` and MRO are closely related.

---

# Advantages

* ✅ Avoids hardcoding parent class names.
* ✅ Supports multiple inheritance correctly.
* ✅ Follows the MRO automatically.
* ✅ Makes code easier to maintain.
* ✅ Encourages cooperative inheritance.

---

# Drawbacks

* ❌ Can be confusing without understanding MRO.
* ❌ Requires all classes in the inheritance chain to cooperate by using `super()`.
* ❌ In complex hierarchies, debugging the call chain can be harder.

---

# Common Interview Questions

### Q1. What is `super()`?

> A built-in function that calls the next method or constructor according to the MRO.

---

### Q2. Why use `super()` instead of `ParentClass.method(self)`?

> Because it avoids tight coupling, supports multiple inheritance, and follows the MRO automatically.

---

### Q3. Does `super()` always call the immediate parent?

> **No.** It calls the **next class in the MRO**, which may not always be the immediate parent in complex multiple inheritance.

---

### Q4. Where is `super()` commonly used?

* Constructors (`__init__`)
* Overridden methods
* Cooperative multiple inheritance

---

# ⭐ Interview Answer (30 Seconds)

> **"`super()` is a built-in function used to call methods or constructors from the next class in the Method Resolution Order (MRO). It avoids hardcoding parent class names, supports cooperative multiple inheritance, and makes code more maintainable. In production, it is commonly used in constructors and overridden methods to reuse parent functionality while extending behavior."**
