# Exception Handling

## Definition

> **Exception Handling is a mechanism to detect and handle runtime errors using `try`, `except`, `else`, and `finally` so that the program continues gracefully instead of crashing.**

## Analogy

> **Like wearing a seatbelt while driving. Even if an accident happens, you stay safe instead of stopping the journey.**

---

## Real-Life Example (Book Store)

```python
# =================== Exception Handling ===================

definition = (
    "Exception Handling is a mechanism to detect and handle runtime errors "
    "using try, except, else and finally."
)

analogy = (
    "Like wearing a seatbelt while driving. "
    "If an accident happens, you remain safe."
)


class BookStore:                                          # Class (Blueprint)

    def buy_book(self, stock):                            # Instance Method

        try:                                              # Risky code starts

            if stock == 0:                                # Business Validation

                raise ValueError("Book Out Of Stock")     # Manually raise Exception

            print("Book Purchased Successfully")          # Executes if no error occurs

        except ValueError as error:                       # Handles only ValueError

            print(error)                                  # Prints Exception Message

        else:                                             # Executes only when try succeeds

            print("Payment Completed")                    # Success Block

        finally:                                          # Executes every time

            print("Visit Again!")                         # Cleanup / Final Block


store = BookStore()                                       # Object Creation

store.buy_book(0)                                         # Method Call
```

### Output

```text
Book Out Of Stock
Visit Again!
```

# Custom Exception

## Definition

> **A Custom Exception is a user-defined exception created by inheriting from Python's `Exception` class to represent business-specific errors.**

## Analogy

> **A shopping mall creates its own rule: "VIP Membership Required." Python doesn't know this business rule, so we create our own exception.**

---

## Real-Life Example (Book Store)

```python
# =================== Custom Exception ===================

definition = (
    "A Custom Exception is a user-defined exception "
    "created by inheriting Exception."
)

analogy = (
    "Like a shopping mall creating its own business rule."
)


class OutOfStockError(Exception):                         # Custom Exception Class

    pass                                                  # No extra implementation required


class BookStore:                                          # Class

    def buy_book(self, stock):                            # Instance Method

        if stock == 0:                                    # Business Validation

            raise OutOfStockError(                        # Raise Custom Exception

                "Requested Book Is Out Of Stock"

            )

        print("Book Purchased Successfully")


store = BookStore()                                       # Object Creation

try:                                                      # Handle Custom Exception

    store.buy_book(0)

except OutOfStockError as error:

    print(error)
```

### Output

```text
Requested Book Is Out Of Stock
```

# CSV vs JSON vs Parquet

## Definition

> **CSV, JSON, and Parquet are data storage formats. CSV stores tabular data, JSON stores hierarchical key-value data, and Parquet stores compressed columnar data optimized for analytics and big data processing.**

## Analogy

> **CSV = Excel Sheet** 📊
> **JSON = Customer Profile Form** 📝
> **Parquet = Compressed Warehouse** 📦

---

## Real-Life Example (Employee Data)

```python
# =================== CSV vs JSON vs Parquet ===================

import csv                                              # CSV Module
import json                                             # JSON Module

definition = (
    "CSV stores rows and columns. "
    "JSON stores key-value data. "
    "Parquet stores compressed columnar data."
)

analogy = (
    "CSV = Excel Sheet\n"
    "JSON = Employee Profile\n"
    "Parquet = Compressed Data Warehouse"
)

employee = {                                            # Python Dictionary

    "id": 101,
    "name": "Shivam",
    "department": "Engineering",
    "salary": 80000
}

# ---------------- CSV ----------------

with open("employee.csv", "w", newline="") as file:     # Create CSV File

    writer = csv.DictWriter(                            # Create CSV Writer

        file,

        fieldnames=employee.keys()

    )

    writer.writeheader()                                # Write Column Names

    writer.writerow(employee)                           # Write Employee Row

print("CSV Created")

# ---------------- JSON ----------------

with open("employee.json", "w") as file:                # Create JSON File

    json.dump(                                          # Write JSON

        employee,

        file,

        indent=4

    )

print("JSON Created")

print("\nEmployee Dictionary")

print(employee)

print("\nJSON Output")

print(json.dumps(employee, indent=4))                   # Convert Dictionary to JSON String

# ---------------- Parquet ----------------

print("\nParquet stores the same data")
print("in compressed columnar format (used with Pandas/PyArrow).")
```

### Output

```text
CSV Created
JSON Created

Employee Dictionary

{'id': 101, 'name': 'Shivam', 'department': 'Engineering', 'salary': 80000}

JSON Output

{
    "id": 101,
    "name": "Shivam",
    "department": "Engineering",
    "salary": 80000
}

Parquet stores the same data
in compressed columnar format (used with Pandas/PyArrow).
```

# Encapsulation

## Definition

> **Encapsulation is the process of binding data (attributes) and methods (functions) together inside a class while controlling direct access to the data. In Python, it is achieved using public, protected (`_`) and private (`__`) attributes.**

## Analogy

> **Like an ATM. You can withdraw money using buttons, but you cannot directly access or modify the cash stored inside the machine.**

---

## Real-Life Example (Bank Account)

```python
# =================== Encapsulation ===================

definition = (
    "Encapsulation binds data and methods together "
    "while controlling access to data."
)

analogy = (
    "Like an ATM where customers cannot directly access cash."
)


class BankAccount:                                      # Class (Blueprint)

    def __init__(self, name, balance):                  # Constructor

        self.name = name                                # Public Variable

        self.__balance = balance                        # Private Variable (__)


    def deposit(self, amount):                          # Public Method

        self.__balance += amount                        # Private Data Modified Internally

        print("Amount Deposited")


    def show_balance(self):                             # Public Method

        print(f"Current Balance : {self.__balance}")    # Access Private Variable


account = BankAccount("Shivam", 5000)                   # Object Creation

account.deposit(2000)                                   # Public Method Call

account.show_balance()                                  # Access Balance Safely

# print(account.__balance)                              # ❌ Error (Private Variable)
```

### Output

```text
Amount Deposited
Current Balance : 7000
```

# Abstraction

## Definition

> **Abstraction hides implementation details and exposes only essential functionality. In Python, it is commonly implemented using the `abc` module and abstract base classes.**

## Analogy

> **You press the accelerator in a car without needing to know how the engine works internally.**

---

## Real-Life Example (Online Payment)

```python

definition = (
    "Abstraction hides implementation details "
    "and exposes only essential features."
)

analogy = (
    "Driving a car without knowing engine internals."
)


class Payment(ABC):                                    # Abstract Class

    @abstractmethod

    def pay(self):                                     # Abstract Method

        pass                                           # No Implementation


class CardPayment(Payment):                            # Child Class

    def pay(self):                                     # Mandatory Implementation

        print("Card Payment Successful")


payment = CardPayment()                                # Object Creation

payment.pay()                                          # Calls Child Implementation
```

### Output

```text
Card Payment Successful
```

# Abstract Base Classes (ABC)

## Definition

> **An Abstract Base Class (ABC) defines a common interface and forces child classes to implement required methods. Objects cannot be created directly from an abstract class.**

## Analogy

> **A university provides a project template, but every student must implement their own project according to that template.**

## Real-Life Example (Notification System)

    "required methods."

    @abstractmethod

    def send(self):                                    # Abstract Method

# Thread Safety & Race Conditions

## Definition

> **Thread Safety means multiple threads can safely access shared data without causing incorrect results. A Race Condition occurs when multiple threads modify shared data at the same time, making the final result unpredictable. Thread synchronization mechanisms like `Lock` are used to prevent race conditions.**

## Analogy

> **Imagine two cashiers updating the same bank account simultaneously. Without coordination, the final balance may become incorrect. A lock acts like giving only one cashier access to the account at a time.**

---

## Real-Life Example (Bank Account)

```python
# =================== Thread Safety & Race Condition ===================

import threading                                        # Thread Module

definition = (
    "Thread Safety ensures shared data is accessed safely "
    "by multiple threads."
)

analogy = (
    "Only one cashier can update a bank account at a time."
)


balance = 1000                                          # Shared Resource

lock = threading.Lock()                                 # Synchronization Lock


def withdraw():                                         # Thread Function

    global balance                                      # Use Global Variable

    with lock:                                          # Acquire Lock (Only One Thread Enters)

        if balance >= 500:                              # Business Validation

            balance -= 500                              # Modify Shared Data

            print(f"Remaining Balance : {balance}")


t1 = threading.Thread(target=withdraw)                  # Thread 1

t2 = threading.Thread(target=withdraw)                  # Thread 2


t1.start()                                              # Start Thread

t2.start()


t1.join()                                               # Wait Until Thread Completes

t2.join()


print("Final Balance :", balance)
```

### Output

```text
Remaining Balance : 500
Remaining Balance : 0
Final Balance : 0
```

# Deadlocks & Livelocks

## Definition

> **A Deadlock occurs when two or more threads wait forever for each other to release resources. A Livelock occurs when threads keep responding to each other but make no actual progress.**

## Analogy

> **Deadlock:** Two cars enter a one-lane bridge from opposite sides and neither can move.
> **Livelock:** Two polite people keep stepping aside for each other repeatedly but never cross.

---

## Real-Life Example (Deadlock Concept)

```python
# =================== Deadlock Concept ===================

import threading

definition = (
    "Deadlock happens when threads wait forever for each other."
)

analogy = (
    "Two people waiting forever for the other to leave a narrow doorway."
)


lock1 = threading.Lock()                                # Resource A

lock2 = threading.Lock()                                # Resource B


def payment_service():

    with lock1:                                         # Acquire Lock 1

        print("Payment Service Locked Resource A")

        # Waiting for Resource B...


def inventory_service():

    with lock2:                                         # Acquire Lock 2

        print("Inventory Service Locked Resource B")

        # Waiting for Resource A...


print("If both services wait for each other,")
print("a Deadlock may occur.")
```

### Output

```text
If both services wait for each other,
a Deadlock may occur.
```

> **Interview Tip:** In production, deadlocks are avoided by **acquiring locks in a consistent order**, using **timeouts**, or **reducing lock scope**.

# Python Memory Model (Heap vs Stack)

## Definition

> **Python stores objects in Heap Memory, while function calls, local variables (references), and execution frames are managed on the Call Stack. Variables usually hold references to heap objects rather than the objects themselves.**

## Analogy

> **Heap = Warehouse storing products** 📦
> **Stack = Work desk holding labels that point to those products** 🗂️

---

## Real-Life Example

```python
# =================== Heap vs Stack ===================

definition = (
    "Objects live in Heap Memory while local references "
    "are managed on the Call Stack."
)

analogy = (
    "Warehouse stores products. Desk stores labels pointing to them."
)


class Employee:                                         # Class

    def __init__(self, name):                           # Constructor

        self.name = name                                # Object Data Stored In Heap


def create_employee():                                  # Function Call (Stack Frame)

    emp = Employee("Shivam")                            # emp is Reference (Stack)
                                                        # Employee Object Lives In Heap

    print(emp.name)                                     # Access Heap Object


create_employee()                                       # Function Executes

print("Function Finished")
```

### Output

```text
Shivam
Function Finished
```
