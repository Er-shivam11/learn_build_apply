# SOLID Principles

## Definition

> **SOLID is a set of five object-oriented design principles that help create software that is maintainable, scalable, flexible, testable, and loosely coupled.**

---

# One-Line Analogy

> **SOLID is like building a company where every employee has one responsibility, departments are easy to extend, managers can be replaced, teams use common contracts, and dependencies are injected rather than hardcoded.**

---

# S → Single Responsibility Principle (SRP)

## Definition

> **A class should have only one reason to change.**

---

## Bad

```python
class User:

    def save_user(self):
        print("User Saved")

    def send_email(self):
        print("Email Sent")
```

Two responsibilities:

```text
User Management
Email Service
```

---

## Good

```python
class User:

    def save_user(self):
        print("User Saved")


class EmailService:

    def send_email(self):
        print("Email Sent")
```

---

## Interview Line

> One class = One responsibility.

---

# O → Open Closed Principle (OCP)

## Definition

> **Software entities should be open for extension but closed for modification.**

---

## Bad

```python
class Payment:

    def pay(self, method):

        if method == "card":
            print("Card Payment")

        elif method == "upi":
            print("UPI Payment")
```

Every new payment method requires modifying existing code.

---

## Good

```python
class Payment:

    def pay(self):
        pass


class CardPayment(Payment):

    def pay(self):
        print("Card Payment")


class UPIPayment(Payment):

    def pay(self):
        print("UPI Payment")
```

---

## Interview Line

> Extend behavior without modifying existing code.

---

# L → Liskov Substitution Principle (LSP)

## Definition

> **A child class should be replaceable with its parent class without breaking the program.**

---

## Good

```python
class Bird:

    def fly(self):
        print("Flying")


class Sparrow(Bird):
    pass
```

---

## Bad

```python
class Bird:

    def fly(self):
        pass


class Penguin(Bird):

    def fly(self):
        raise Exception("Cannot Fly")
```

Penguin breaks expectations.

---

## Interview Line

> Child should behave like parent.

---

# I → Interface Segregation Principle (ISP)

## Definition

> **Clients should not be forced to depend on methods they do not use.**

---

## Bad

```python
class Worker:

    def work(self):
        pass

    def eat(self):
        pass
```

Robot doesn't eat.

---

## Good

```python
class Workable:

    def work(self):
        pass


class Eatable:

    def eat(self):
        pass
```

---

## Interview Line

> Small focused interfaces are better than large ones.

---

# D → Dependency Inversion Principle (DIP)

## Definition

> **High-level modules should depend on abstractions, not concrete implementations.**

---

## Bad

```python
class MySQL:

    pass


class UserService:

    def __init__(self):
        self.db = MySQL()
```

Tightly coupled.

---

## Good

```python
class Database:

    pass


class MySQL(Database):

    pass


class UserService:

    def __init__(self, db):
        self.db = db
```

---

## Interview Line

> Depend on abstractions, not implementations.

# Quick Revision

| Principle | Meaning               |
| --------- | --------------------- |
| S         | Single Responsibility |
| O         | Open Closed           |
| L         | Liskov Substitution   |

| D         | Dependency Inversion  |

# Real E-commerce Mapping

| Principle | Example                                               |
| --------- | ----------------------------------------------------- |
| SRP       | UserService and EmailService separate                 |
| OCP       | Add new payment method without changing existing code |
| LSP       | CreditCardPayment can replace Payment                 |
| ISP       | Separate Payment and Refund interfaces                |
| DIP       | OrderService depends on Database abstraction          |

# Advantages

* ✅ Maintainable
* ✅ Scalable
* ✅ Reusable
* ✅ Testable
* ✅ Loose Coupling

---

# Drawbacks

* ❌ More classes
* ❌ More abstraction
* ❌ Overkill for very small projects

---

# Common Interview Questions

### Q1. What is SOLID?

> Five OOP design principles for maintainable software.

---

### Q2. Which SOLID principle is most violated?

> SRP (Single Responsibility Principle).

---

### Q3. Which principle do decorators follow?

> Open Closed Principle (OCP).

---

### Q4. Which principle leads to Dependency Injection?

> Dependency Inversion Principle (DIP).

---

### Q5. Why is SOLID important?

> It reduces coupling and improves maintainability.

---

# ⭐ Interview Answer (30 Seconds)

> **"SOLID is a set of five object-oriented design principles: Single Responsibility, Open Closed, Liskov Substitution, Interface Segregation, and Dependency Inversion. Together they promote maintainable, extensible, loosely coupled, and testable software. In modern backend systems, SOLID helps manage complexity and supports scalable architecture."**
