# Decorators (Complete Interview Guide)

---

# 1. What is a Decorator?

> **Interview Answer (30 sec)**

A **decorator** is a design pattern in Python used to **extend or modify the behavior of a function or class without changing its original source code**.

It works because Python treats **functions as first-class objects**, allowing them to be passed, returned, and assigned like normal variables.

Internally,

```python
def decorator(func):
    def wrapper():
        print("Before")
        func()
        print("After")
    return wrapper
@decorator
def employee():
    print("hello")
    # employee = decorator(employee)=@decorator is knows as syntactic sugar
employee()
```

This follows the **Open-Closed Principle**:

* Open for extension
* Closed for modification

---

# Real Life Analogy

A decorator is like a security guard who checks you before and after you enter the office without changing who you are.

# 5. Why Wrapper?

Wrong

```python
def logger(func):
    func()
```

Runs immediately.

Correct

```python
def logger(func):

    def wrapper():

        func()

    return wrapper
```

Wrapper delays execution until someone calls the function.

# 6. Decorator with Parameters (*args, **kwargs)

Suppose

```python
def update_salary(emp_id, amount):
```

Decorator should work.

```python
def logger(func):

    def wrapper(*args, **kwargs):

        print("Updating Employee")

        result = func(*args, **kwargs)

        print("Updated Successfully")

        return result

    return wrapper


@logger
def update_salary(emp_id, amount):

    print(emp_id, amount)


update_salary(101,50000)
```

Output

```
Updating Employee

101 50000

Updated Successfully
```

Why `*args`?

Decorator should work for **any** function signature.

# 7. Preserving Metadata (@wraps)

Without

```python
print(update_salary.__name__)
```

Output

```
wrapper
```

Not

```

```

Fix

```python
from functools import wraps

def logger(func):

    @wraps(func)
    def wrapper(*args, **kwargs):

        return func(*args, **kwargs)

    return wrapper
```

Now

```

```

# 8. Parameterized Decorator (Decorator Factory)

Suppose company policy says

Repeat welcome email 3 times.

```python
def repeat(times):

    def decorator(func):

        def wrapper(*args, **kwargs):

            for _ in range(times):

                func(*args, **kwargs)

        return wrapper

    return decorator


@repeat(3)
def welcome_employee():

    print("Welcome Shivam")


welcome_employee()
```

Output

```
Welcome Shivam

Welcome Shivam

Welcome Shivam
```

# 17. Common Interview Questions

### Q1. Why nested functions?

To create a **closure**, allowing the wrapper to remember the original function even after the outer function has finished execution.

---

### Q2. What is a closure?

A closure is an inner function that remembers variables from its enclosing scope even after the outer function returns. In decorators, the wrapper remembers the original function (`func`) using a closure.

---

### Q3. Why use `*args` and `**kwargs`?

To make the decorator generic so it can wrap functions with any number of positional or keyword arguments.

---

### Q4. Why use `functools.wraps`?

It preserves the original function's metadata such as `__name__`, `__doc__`, and annotations, which helps with debugging, documentation, and introspection.

---

### Q5. Can decorators return values?

Yes. The wrapper should return the original function's result so callers receive the expected output.

---

### Q6. Can decorators modify arguments or skip execution?

Yes. They can validate, transform arguments, or even prevent the original function from running (for example, when authentication fails).

---

### Q7. Can decorators be applied to async functions or classes?

Yes. They can decorate regular functions, methods, async functions, generators, and even classes. For async functions, the wrapper itself should be `async` and use `await`.

# Iterators

## Definition

> **An iterator is an object that returns one element at a time from a collection using the `__next__()` method. It keeps track of its current position and raises `StopIteration` when no elements remain. An iterator is created from an iterable using the `iter()` function.**

---

## One-Line Analogy

> **Think of a TV remote: every time you press the "Next" button, it moves to the next channel. When there are no more channels, it stops.**

# How a `for` Loop Works Internally

When you write:

```python
orders = ["Laptop", "Mouse", "Keyboard"]

for order in orders:
    print(order)
```

Python actually does this internally:

```python
orders = ["Laptop", "Mouse", "Keyboard"]

iterator = iter(orders)

while True:
    try:
        item = next(iterator)
        print(item)
    except StopIteration:
        break
```

### Output

```text
Laptop
Mouse
Keyboard
```

---

# Custom Iterator Example

```python
class OrderIterator:

    def __init__(self):
        self.orders = ["Laptop", "Mouse", "Keyboard"]
        self.index = 0

    def __iter__(self):
        return self

    def __next__(self):
        if self.index >= len(self.orders):
            raise StopIteration

        order = self.orders[self.index]
        self.index += 1
        return order


orders = OrderIterator()

for order in orders:
    print(order)
```

### Output

```text
Laptop
Mouse
Keyboard
```

## Definition

> **A generator is a special type of iterator that produces one value at a time using the `yield` keyword instead of returning all values at once. It supports lazy evaluation, making it highly memory efficient for processing large datasets.**

# Closures

## Definition

> **A closure is an inner function that remembers and can access variables from its enclosing (outer) function even after the outer function has finished executing. This is possible because Python preserves the enclosing scope.**

---

## One-Line Analogy

> **Think of a waiter taking your order and remembering it even after leaving your table. The waiter (inner function) remembers your order (outer variable).**

---

# Real-Life Example (E-commerce)

```python
def order(customer):

    def invoice():
        print(f"Invoice generated for {customer}")

    return invoice


bill = order("Shivam")

bill()
```

### Output

```text
Invoice generated for Shivam
```

---

# What Happens Internally?

```text
order("Shivam")

        ↓

customer = "Shivam"

        ↓

invoice()

        ↓

Returned

        ↓

order() Finished

        ↓

invoice() Still Remembers

        ↓

customer = "Shivam"

        ↓

bill()
```

---

# Why is it Called a Closure?

Because the inner function **"closes over"** the variables of the outer function.

Example:

```python
def employee(name):

    def display():
        print(name)

    return display
```

Even after `employee()` finishes, `display()` still remembers `name`.

---

Here, `name` is still available because the closure preserves it.

# Relationship with Decorators

A decorator is built using a closure.

```python
def logger(func):

    def wrapper():
        print("Before")

        func()

        print("After")

    return wrapper
```

The `wrapper()` function remembers `func`.

That remembered variable is exactly what makes this a **closure**.

---

# Advantages

* ✅ Remembers state without global variables
* ✅ Data hiding
* ✅ Cleaner than global variables
* ✅ Foundation of decorators
* ✅ Useful for callbacks and function factories

---

# Drawbacks

* ❌ Can consume memory if many closures are created
* ❌ Harder to debug
* ❌ Can be confusing for beginners

---

# Common Interview Questions

### Q1. What is a closure?

> An inner function that remembers variables from its enclosing scope even after the outer function has returned.

---

### Q2. Why are closures used?

> To preserve state without using global variables or classes.

---

### Q3. Why do decorators use closures?

> Because the wrapper function must remember the original function (`func`) after the decorator has finished executing.

---

### Q4. Does a closure copy the variable?

> No. It keeps a reference to the variable from the enclosing scope.

---

### Q5. Can a closure modify the outer variable?

Yes, using `nonlocal`.

```python
def counter():

    count = 0

    def increment():
        nonlocal count
        count += 1
        print(count)

    return increment


c = counter()

c()
c()
```

### Output

```text
1
2
```

> **"A closure is an inner function that remembers variables from its enclosing scope even after the outer function has completed execution. This preserved state allows functions to maintain data without using global variables. Closures are commonly used in decorators, callbacks, and function factories."**

# GIL (Global Interpreter Lock)

## 1. Definition (30 sec Interview Answer)

> **The Global Interpreter Lock (GIL) is a mutex in CPython that allows only one thread to execute Python bytecode at a time within a single process. It simplifies memory management by protecting Python objects from concurrent access, but it prevents true parallel execution of CPU-bound Python threads.**

---

```text
Whole Python Process
```

```text

↓

↓

```

---

### Lock

Think of a lock on a room.

```text
Only one person can enter.

Others wait outside.
```

Exactly the same.

# 10. Interview Summary

| Scenario        | Best Choice     | Why                                                                                                                  |
| --------------- | --------------- | -------------------------------------------------------------------------------------------------------------------- |
| CPU-bound tasks | Multiprocessing | Each process has its own Python interpreter and its own GIL, allowing true parallel execution on multiple CPU cores. |
| I/O-bound tasks | Multithreading  | Threads spend much of their time waiting for I/O, and the GIL is released during those waits, improving throughput.  |

---

## 30-Second Interview Answer

> **The GIL (Global Interpreter Lock) is a mutex in CPython that ensures only one thread executes Python bytecode at a time within a process. It simplifies memory management and prevents race conditions on Python objects. Because of the GIL, multithreading is effective for I/O-bound tasks, where threads frequently wait and release the GIL, but it doesn't provide true parallelism for CPU-bound tasks. For CPU-intensive workloads, multiprocessing is preferred because each process has its own interpreter and its own GIL.**

# MRO (Method Resolution Order)

## Definition (30 Seconds)

> **MRO (Method Resolution Order) is the order in which Python searches for methods and attributes in an inheritance hierarchy, especially in multiple inheritance. Python uses the C3 Linearization algorithm to determine a consistent, predictable, and conflict-free method lookup order.**

---

## One-Line Analogy

> **Imagine an online order asks multiple departments for help. Python follows a predefined priority list (MRO). It asks the first department; if the method is found, it stops and never asks the remaining departments.**

---

## Real-Life Example (E-commerce)

```python
class Payment:

    def process(self):
        print("Payment Done")


class Discount:

    def process(self):
        print("Discount Applied")


class Order(Payment, Discount):
    pass


order = Order()

order.process()

print(Order.mro())
```

### Output

```text
Payment Done

[<class '__main__.Order'>,
 <class '__main__.Payment'>,
 <class '__main__.Discount'>,
 <class 'object'>]
```

---

## How MRO Works

When you call

```python
order.process()
```

Python searches like this:

```text
Order
   ↓
Payment   ✅ Found process()
   ↓
Discount  ❌ Not Checked
   ↓
object
```

As soon as the method is found, Python **stops searching**.

---

## Changing the MRO

Simply change the inheritance order:

```python
class Order(Discount, Payment):
    pass
```

Now the MRO becomes:

```text
Order
   ↓
Discount
   ↓
Payment
   ↓
object
```

Output

```text
Discount Applied
```

---

## Why MRO is Needed?

Without MRO, Python wouldn't know **which parent's method to execute** when multiple parent classes define the same method.

MRO provides a **single, deterministic lookup order**.

---

## C3 Linearization Rules

1. Child class is searched first.
2. Parent classes are searched from left to right.
3. Each class appears only once.
4. The order is consistent and conflict-free.

---

## Advantages

* ✅ Resolves method conflicts in multiple inheritance.
* ✅ Provides a predictable and consistent lookup order.
* ✅ Prevents ambiguity.
* ✅ Supports `super()` correctly.
* ✅ Enables safe use of multiple inheritance.

---

## Drawbacks

* ❌ Can become difficult to understand with deep inheritance hierarchies.
* ❌ Changing the inheritance order changes method resolution.
* ❌ Debugging can be harder in complex multiple inheritance.
* ❌ Poor class design can lead to the "Diamond Problem," although Python's MRO resolves it.

---

## Common Interview Questions

### Q1. What is MRO?

> The order in which Python searches for methods and attributes in an inheritance hierarchy.

---

### Q2. Which algorithm does Python use?

> **C3 Linearization**.

---

### Q3. How do you check the MRO?

```python
print(Order.mro())
```

or

```python
help(Order)
```

---

### Q4. Why is MRO important?

> It resolves ambiguity when multiple parent classes define the same method.

---

### Q5. Does Python search all parent classes?

> **No.** Python stops searching as soon as it finds the required method according to the MRO.

---

### Q6. How can you change the MRO?

> By changing the inheritance order.

```python
class Order(Payment, Discount):
```

↓

```python
class Order(Discount, Payment):
```

---

## 30-Second Interview Answer

> **"MRO (Method Resolution Order) defines how Python searches for methods and attributes in an inheritance hierarchy, especially in multiple inheritance. Python follows the C3 Linearization algorithm, which searches the child class first and then parent classes from left to right while maintaining a consistent and conflict-free order. We can inspect the MRO using `ClassName.mro()`. This mechanism also enables `super()` to work correctly and resolves ambiguity when multiple parent classes implement the same method."**

---

# Shallow Copy vs Deep Copy

## Definition

> **A shallow copy creates a new outer object but shares references to nested objects with the original. A deep copy creates a completely independent copy of both the outer object and all nested objects recursively.**

---

## One-Line Analogy

> **A shallow copy is like photocopying a house map but using the same furniture. A deep copy is like building a completely new house with new furniture.**

---

# Real-Life Example (E-commerce)

**Scenario:** An order contains customer details. We duplicate the order before editing it.

```python
import copy

order = {
    "id": 101,
    "items": ["Laptop", "Mouse"]
}

shallow = copy.copy(order)
deep = copy.deepcopy(order)

shallow["items"].append("Keyboard")
deep["items"].append("Monitor")

print("Original :", order)
print("Shallow :", shallow)
print("Deep     :", deep)
```

### Output

```text
Original : {'id': 101, 'items': ['Laptop', 'Mouse', 'Keyboard']}
Shallow : {'id': 101, 'items': ['Laptop', 'Mouse', 'Keyboard']}
Deep     : {'id': 101, 'items': ['Laptop', 'Mouse', 'Monitor']}
```

---

# What Happens Internally?

## Original Object

```text
order
   │
   ▼

Dictionary
   │
   ├── id → 101
   │
   └── items ─────────► ["Laptop","Mouse"]
```

---

## Shallow Copy

```python
shallow = copy.copy(order)
```

```text
order ─────────────┐
                   │
                   ▼
              ["Laptop","Mouse"]
                   ▲
                   │
shallow ───────────┘
```

Both dictionaries are different, **but the `items` list is shared**.

When you do

```python
shallow["items"].append("Keyboard")
```

Both see the change.

---

## Deep Copy

```python
deep = copy.deepcopy(order)
```

```text
order ─────► ["Laptop","Mouse"]

deep ──────► ["Laptop","Mouse"]
```

Each object has its **own independent list**.

Changing one does **not** affect the other.

---

# When to Use?

### Shallow Copy

Use when:

* Nested objects don't need to be modified.
* You want better performance.
* Sharing nested data is acceptable.

---

### Deep Copy

Use when:

* You need a completely independent object.
* Nested lists or dictionaries will be modified.
* You want to avoid side effects.

---

# Advantages

### Shallow Copy

* ✅ Faster
* ✅ Uses less memory
* ✅ Suitable for simple structures

---

### Deep Copy

* ✅ Completely independent copy
* ✅ Safe for nested mutable objects
* ✅ No accidental shared changes

---

# Drawbacks

### Shallow Copy

* ❌ Nested mutable objects are shared.
* ❌ Can lead to unexpected bugs.

---

### Deep Copy

* ❌ Slower
* ❌ Uses more memory
* ❌ Can be expensive for very large objects

---

# Common Interview Questions

### Q1. What is a shallow copy?

> A new outer object is created, but nested objects are shared with the original.

---

### Q2. What is a deep copy?

> A completely independent copy of the object and all nested objects.

---

### Q3. Which module is used?

```python
import copy
```

---

### Q4. How do you create them?

```python
copy.copy(obj)
```

```python
copy.deepcopy(obj)
```

---

### Q5. Why is shallow copy dangerous?

> Because modifying a shared nested mutable object affects both the original and the copied object.

---

# ⭐ Interview Answer (30 Seconds)

> **"A shallow copy creates a new outer object while sharing references to nested mutable objects. A deep copy recursively creates completely independent copies of all nested objects. Shallow copies are faster and use less memory, whereas deep copies provide complete isolation and are safer when modifying nested data."**

# Python Execution Flow

## Definition

> **Python Execution Flow is the process by which Python reads source code, compiles it into bytecode, and executes it using the Python Virtual Machine (PVM). During execution, Python manages function calls through stack frames while storing objects in heap memory.**

---

## One-Line Analogy

> **Think of Python as a translator: it reads an English recipe (source code), converts it into instructions (bytecode), and the chef (PVM) executes those instructions step by step.**

---

# Real-Life Example (E-commerce)

```python
def place_order():
    print("Order Placed")


place_order()
```

### Output

```text
Order Placed
```

---

# Execution Flow

```text
Source Code (.py)

        ↓

Python Compiler

        ↓

Bytecode (.pyc)

        ↓

Python Virtual Machine (PVM)

        ↓

Output
```

---

# What Happens Internally?

```text

        ↓

Function Call

        ↓

Stack Frame Created

        ↓

Execute Bytecode

        ↓

Print Output

        ↓

Stack Frame Removed
```

---

# Key Components

### 1. Source Code

```python
def place_order():
    print("Order Placed")
```

Human-readable Python code.

---

### 2. Compiler

Python first compiles the source code into **bytecode**.

---

### 3. Bytecode

Intermediate instructions stored as:

```text
.pyc
```

Python executes bytecode instead of the original `.py` file.

---

### 4. Python Virtual Machine (PVM)

The PVM reads and executes the bytecode instruction by instruction.

---

### 5. Stack Frame

Each function call creates a new stack frame containing:

* Local variables
* Parameters
* Return address

When the function finishes, its stack frame is removed.

---

### 6. Heap Memory

Objects created during execution (lists, dictionaries, class instances, etc.) are stored in the heap.

---

# Advantages

* ✅ Platform independent (same bytecode works wherever Python is available).
* ✅ Faster execution after compilation to bytecode.
* ✅ Automatic memory management.
* ✅ Simplifies program execution.

---

# Drawbacks

* ❌ Slower than compiled languages like C/C++.
* ❌ Bytecode still needs interpretation by the PVM.
* ❌ Startup overhead compared to native binaries.

---

# Common Interview Questions

> **Yes. Python first compiles source code into bytecode before execution.**

---

### Q2. What is bytecode?

> **Bytecode is an intermediate, platform-independent representation of Python code executed by the PVM.**

---

### Q3. What is a `.pyc` file?

> **A compiled bytecode file generated by Python to improve startup performance.**

---

### Q4. What is the PVM?

> **The Python Virtual Machine executes Python bytecode instruction by instruction.**

---

### Q5. What is a stack frame?

> **A stack frame is created for every function call and stores local variables, parameters, and execution information.**

---

During execution, each function call creates a stack frame, while objects are allocated in heap memory and managed automatically through reference counting and garbage collection."**

# Garbage Collection (GC)

## Definition

> **Garbage Collection (GC) is Python's automatic memory cleanup mechanism that removes objects that are no longer in use. In CPython, memory is managed primarily through reference counting, while the garbage collector detects and cleans up circular references that reference counting alone cannot free.**

---

## One-Line Analogy

> **Imagine a hotel: when no guest is using a room, housekeeping automatically cleans it so it can be reused.**

---

# Real-Life Example (E-commerce)

```python

    def __init__(self, order_id):
        self.order_id = order_id


order = Order(101)

print("Order Created")

del order

print("Order Deleted")
```

### Output

```text
Order Created
Order Deleted
```

---

# Reference Counting Example

```python

another = order

print(sys.getrefcount(order))
```

### Possible Output

```text

3
```

*(The exact numbers may vary because `getrefcount()` temporarily adds one reference.)*

---

# Circular Reference Example

```python
class Customer:
    pass


class Order:
    pass


customer = Customer()
order = Order()

customer.order = order
order.customer = customer

del customer
del order

print("Circular reference created")
```

Python's **Garbage Collector** will detect and clean this cycle because reference counting alone cannot.

---

```text

        ↓

        ↓

        ↓

        ↓

        ↓

        ↓

-----------------------------

        ↓

        ↓

        ↓

```

---

# Why Garbage Collection is Needed?

Reference counting works well for most objects.

But consider this:

```text
Customer
    │
    ▼
Order

▲      │
│      ▼

Customer
```

Even if you remove external references,

```python
del customer
del order
```

both objects still reference each other.

Reference count never reaches **0**.

That's why Python's **Garbage Collector** exists.

---

# Advantages

* ✅ Automatic memory cleanup
* ✅ Prevents most memory leaks
* ✅ Handles circular references
* ✅ Developers rarely free memory manually

---

# Drawbacks

* ❌ Small runtime overhead
* ❌ Garbage collection may pause execution briefly
* ❌ Large object graphs can take longer to scan

---

---

### Q2. What is Reference Counting?

---

### Q3. Why is Garbage Collection needed if Python has reference counting?

> Because reference counting cannot detect and free **circular references**.

---


---



However, reference counting cannot handle circular references, so Python also includes a garbage collector that periodically detects and removes cyclic objects. Together, these mechanisms provide automatic memory management."**

# Context Managers

## Definition

> **A Context Manager is an object that automatically manages resources such as files, database connections, locks, or network connections by setting them up before use and cleaning them up afterward. It is typically used with the `with` statement and implemented using the `__enter__()` and `__exit__()` methods.**

---

## One-Line Analogy

> **Think of a hotel: you check in (`__enter__()`), stay in the room (your code), and check out (`__exit__()`). The hotel automatically handles opening and closing your stay.**

---

# Real-Life Example (File Handling)

```python
with open("sample.txt", "w") as file:
    file.write("Hello Shivam")
```

### Output

```text
sample.txt created successfully
```

The file is **automatically closed**, even if an exception occurs.

---

# What Happens Internally?

```text
with open(...)

        ↓

__enter__()

        ↓

Resource Opened

        ↓

Your Code Executes

        ↓

__exit__()

        ↓

Resource Closed
```

---

# Without Context Manager

```python
file = open("sample.txt", "w")

file.write("Hello Shivam")

file.close()
```

If an exception occurs before `close()`, the file may remain open.

---

# With Context Manager

```python
with open("sample.txt", "w") as file:
    file.write("Hello Shivam")
```

Python guarantees the resource is cleaned up.

---

# Custom Context Manager

```python
class Database:

    def __enter__(self):
        print("Database Connected")
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        print("Database Closed")


with Database():
    print("Fetching Employees")
```

### Output

```text

Fetching Employees
Database Closed
```
