# Decorators (Complete Interview Guide)

---

# 1. What is a Decorator?

> **Interview Answer (30 sec)**

A **decorator** is a design pattern in Python used to **extend or modify the behavior of a function or class without changing its original source code**.

It works because Python treats **functions as first-class objects**, allowing them to be passed, returned, and assigned like normal variables.

Internally,

```python
def decorator(func):
    def wrapper():
        print("Before")
        func()
        print("After")
    return wrapper
@decorator
def employee():
    print("hello")
    # employee = decorator(employee)=@decorator is knows as syntactic sugar
employee()
```

This follows the **Open-Closed Principle**:

* Open for extension
* Closed for modification

---

# Real Life Analogy

A decorator is like a security guard who checks you before and after you enter the office without changing who you are.

# 2. Why use Decorators?

Suppose every employee action requires

* Logging
* Authentication
* Timing
* Permission Check

Without decorators

```python
login()
log()
permission()
employee_salary()
```

Repeated everywhere.

Instead

```python
@logger
@permission
def employee_salary():
    ...
```

Cleaner and reusable.

# 3. Why are Decorators Possible?

Because **functions are first-class objects.**

Functions can

Assign

```python
a = employee
```

Pass

```python
manager(employee)
```

Return

```python
return employee
```

Store

```python
employees.append(employee)
```

Without first-class functions,
decorators wouldn't exist.

# 4. Simplest Decorator

Employee Management Example

```python
def logger(func):

    def wrapper():
        print("Log: Employee request started")

        func()

        print("Log: Employee request completed")

    return wrapper


@logger
def view_employee():

    print("Employee Details")


view_employee()
```

Output

```
Log: Employee request started

Employee Details

Log: Employee request completed
```

# 5. Why Wrapper?

Wrong

```python
def logger(func):
    func()
```

Runs immediately.

Correct

```python
def logger(func):

    def wrapper():

        func()

    return wrapper
```

Wrapper delays execution until someone calls the function.

# 6. Decorator with Parameters (*args, **kwargs)

Suppose

```python
def update_salary(emp_id, amount):
```

Decorator should work.

```python
def logger(func):

    def wrapper(*args, **kwargs):

        print("Updating Employee")

        result = func(*args, **kwargs)

        print("Updated Successfully")

        return result

    return wrapper


@logger
def update_salary(emp_id, amount):

    print(emp_id, amount)


update_salary(101,50000)
```

Output

```
Updating Employee

101 50000

Updated Successfully
```

Why `*args`?

Decorator should work for **any** function signature.

# 7. Preserving Metadata (@wraps)

Without

```python
print(update_salary.__name__)
```

Output

```
wrapper
```

Not

```
update_salary
```

Fix

```python
from functools import wraps

def logger(func):

    @wraps(func)
    def wrapper(*args, **kwargs):

        return func(*args, **kwargs)

    return wrapper
```

Now

```
update_salary
```

# 8. Parameterized Decorator (Decorator Factory)

Suppose company policy says

Repeat welcome email 3 times.

```python
def repeat(times):

    def decorator(func):

        def wrapper(*args, **kwargs):

            for _ in range(times):

                func(*args, **kwargs)

        return wrapper

    return decorator


@repeat(3)
def welcome_employee():

    print("Welcome Shivam")


welcome_employee()
```

Output

```
Welcome Shivam

Welcome Shivam

Welcome Shivam
```

# 9. Multiple Decorators

Example

```python

```

Internally

```python
delete_employee = logger(authentication(delete_employee))
```

Execution

```
Function Call → Wrapper Executes → Before Code → Original Function → After Code → Return Result
```

# 10. Class Decorator

Book Management

```python
def audit(cls):

    class Wrapper(cls):

        def issue_book(self):

            print("Audit Started")

            super().issue_book()

            print("Audit Completed")

    return Wrapper


@audit
class Library:

    def issue_book(self):

        print("Book Issued")


library = Library()

library.issue_book()
```

Output

```
Audit Started

Book Issued

Audit Completed
```

# 11. Class-Based Decorator

Instead of function

```python
class Logger:

    def __init__(self, func):

        self.func = func

    def __call__(self):

        print("Started")

        self.func()

        print("Finished")


@Logger
def employee():

    print("Employee Updated")


employee()
```

Output

```
Started

Employee Updated

Finished
```

# 12. Built-in Decorators

## @staticmethod

No object required.

```python
class Employee:

    @staticmethod
    def company():

        print("Google")


Employee.company()
```

---

## @classmethod

Works with class.

```python
class Employee:

    count = 120

    @classmethod
    def total_employee(cls):

        print(cls.count)
```

---

## @property

Treat method like variable.

```python
class Employee:

    @property
    def company(self):

        return "Google"

emp = Employee()

print(emp.company)
```

instead of

```
emp.company()
```

# 15. Drawbacks

Debugging becomes harder.

Execution order can confuse developers.

Missing `@wraps` loses metadata.

Every decorator adds a small runtime overhead.

Too many decorators reduce readability.

# 17. Common Interview Questions

### Q1. Why nested functions?

To create a **closure**, allowing the wrapper to remember the original function even after the outer function has finished execution.

---

### Q2. What is a closure?

A closure is an inner function that remembers variables from its enclosing scope even after the outer function returns. In decorators, the wrapper remembers the original function (`func`) using a closure.

---

### Q3. Why use `*args` and `**kwargs`?

To make the decorator generic so it can wrap functions with any number of positional or keyword arguments.

---

### Q4. Why use `functools.wraps`?

It preserves the original function's metadata such as `__name__`, `__doc__`, and annotations, which helps with debugging, documentation, and introspection.

---

### Q5. Can decorators return values?

Yes. The wrapper should return the original function's result so callers receive the expected output.

---

### Q6. Can decorators modify arguments or skip execution?

Yes. They can validate, transform arguments, or even prevent the original function from running (for example, when authentication fails).

---

### Q7. Can decorators be applied to async functions or classes?

Yes. They can decorate regular functions, methods, async functions, generators, and even classes. For async functions, the wrapper itself should be `async` and use `await`.
