# Phase 6 — PostgreSQL

PostgreSQL provides many advanced features beyond standard SQL, making it a popular choice for backend systems, analytics platforms, and data engineering pipelines.

---

# 39. JSONB

## Definition

**JSONB is PostgreSQL's binary JSON data type that stores JSON efficiently and supports indexing, searching, and querying individual fields.**

---

## Why

Applications often receive flexible JSON data from APIs.

Instead of creating many columns,

store the JSON directly.

---

## Analogy

A customer profile folder.

Some customers have

Phone

Email

Address

Others may also have

Skills

Certificates

Social Links

JSONB allows flexible storage.

---

## Syntax

```sql
CREATE TABLE customers(

    customer_id INT,

    profile JSONB

);
```

---

## Fully Commented SQL

```sql
INSERT INTO customers

VALUES(

1,

'{

"name":"Shivam",

"city":"Mumbai",

"skills":["Python","SQL"]

}'

);

------------------------------------------------

SELECT

profile->>'city'          -- Extract city

FROM customers;
```

---

## Execution

```text
Application

↓

JSON

↓

JSONB Column

↓

Query Individual Keys
```

---

## Drawbacks

* More complex than normal columns.
* Overusing JSONB can reduce relational benefits.

---

## Quick Revision

* Flexible Data
* Binary Storage
* Index Supported
* API Friendly

# 40. Functions

## Definition

A **Function** is a reusable block of SQL or procedural code that accepts inputs and returns a value.

---

## Why

Avoid repeating SQL logic.

---

## Analogy

Python Function

Write once.

Call many times.

---

## Syntax

```sql
CREATE FUNCTION
```

---

## Fully Commented SQL

```sql
CREATE FUNCTION total_tax(

amount NUMERIC

)

RETURNS NUMERIC

AS $$

BEGIN

RETURN amount*0.18;

END;

$$

LANGUAGE plpgsql;
```

Call

```sql
SELECT total_tax(1000);
```

---

## Execution

```text
Input

↓

Function

↓

Output
```

---

## Drawbacks

Complex functions may reduce readability.

---

## Quick Revision

* Reusable
* Accepts Parameters
* Returns Value

---

# 41. Stored Procedures

## Definition

A **Stored Procedure** is a reusable database program that performs one or more operations and may not return a value.

---

## Why

Useful for business workflows involving multiple SQL statements.

---

## Analogy

ATM Cash Withdrawal

One button

↓

Many internal operations

---

## Syntax

```sql
CREATE PROCEDURE
```

---

## Fully Commented SQL

```sql
CREATE PROCEDURE increase_salary()

LANGUAGE plpgsql

AS $$

BEGIN

UPDATE employees

SET salary=salary+5000;

END;

$$;
```

Execute

```sql
CALL increase_salary();
```

---

## Execution

```text
CALL

↓

Procedure

↓

Multiple SQL Statements
```

---

## Drawbacks

Business logic inside the database may become difficult to maintain.

---

## Quick Revision

* Reusable Workflow
* Multiple SQL Statements
* CALL

---

# Function vs Stored Procedure

| Function       | Procedure                |
| -------------- | ------------------------ |
| Returns Value  | Usually performs actions |
| Used in SELECT | Called with CALL         |
| Smaller Logic  | Larger Workflow          |

# 42. Triggers

## Definition

A **Trigger** automatically executes when INSERT, UPDATE, or DELETE occurs on a table.

---

## Why

Automatically maintain logs, audit tables, or validation.

---

## Analogy

Motion Sensor Light.

Someone enters.

↓

Light turns ON automatically.

---

## Syntax

```sql
CREATE TRIGGER
```

---

## Fully Commented SQL

```sql
CREATE TRIGGER audit_trigger

AFTER INSERT

ON orders

FOR EACH ROW

EXECUTE FUNCTION log_orders();
```

---

## Execution

```text
INSERT

↓

Trigger Fires

↓

Audit Table Updated
```

---

## Drawbacks

Hidden execution can make debugging difficult.

---

## Quick Revision

* Automatic
* Event Driven
* INSERT
* UPDATE
* DELETE

# 43. Vacuum

## Definition

**VACUUM reclaims storage occupied by dead tuples and keeps PostgreSQL tables efficient.**

---

## Why

PostgreSQL uses MVCC.

Old row versions remain after UPDATE or DELETE.

VACUUM cleans them.

---

## Analogy

Cleaning a classroom.

Students leave.

Trash remains.

Cleaner removes trash.

---

## Syntax

```sql
VACUUM orders;
```

---

## Execution

```text
UPDATE

↓

Old Version

↓

Dead Tuple

↓

VACUUM

↓

Space Reused
```

---

## Drawbacks

Can consume resources on very large tables.

---

## Quick Revision

* Removes Dead Tuples
* Frees Space
* Improves Performance

---

# 44. Replication

## Definition

**Replication copies data from one PostgreSQL server to one or more replica servers.**

---

## Why

Provides

* High Availability
* Disaster Recovery
* Read Scaling

---

## Analogy

Photocopying an important file.

Original remains.

Copies are available if needed.

---

## Execution

```text
Primary Database

↓

Replica 1

↓

Replica 2

↓

Replica 3
```

---

## Drawbacks

Replication lag may occur.

Replicas might briefly have older data.

---

## Quick Revision

* Backup
* Read Scaling
* High Availability

---

# 45. Connection Pooling

## Definition

**Connection Pooling reuses existing database connections instead of creating a new connection for every request.**

---

## Why

Opening database connections is expensive.

Pooling improves performance.

---

## Analogy

Taxi Stand.

Instead of buying a new taxi every trip,

reuse available taxis.

---

## Execution

Without Pool

```text
Request

↓

Open Connection

↓

Execute SQL

↓

Close Connection
```

With Pool

```text
Pool

↓

Reuse Connection

↓

Execute SQL

↓

Return to Pool
```

---

## Drawbacks

Poor pool configuration can cause idle or exhausted connections.

---

## Common Tools

* PgBouncer
* Pgpool-II

---

## Quick Revision

* Reuse Connections
* Faster Requests
* Better Scalability
