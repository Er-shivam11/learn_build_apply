# Phase 7 — Data Engineering

Modern Data Engineering is not just about writing SQL—it is about moving, transforming, and maintaining large volumes of data efficiently.

---

# 46. OLTP vs OLAP

## Definition

* **OLTP (Online Transaction Processing)** handles day-to-day transactional operations like INSERT, UPDATE, DELETE, and small SELECT queries.
* **OLAP (Online Analytical Processing)** is designed for analytical queries, reporting, dashboards, and business intelligence over large datasets.

---

## Why

Businesses need **two different systems**:

* One to **run the business**.
* One to **analyze the business**.

---

## Analogy

Restaurant

```text
Kitchen
↓

Take Orders

Cook Food

Serve Customers

↓

OLTP

------------------

Manager

↓

Monthly Sales

Best Selling Dish

Revenue Analysis

↓

OLAP
```

---

## Comparison

| OLTP               | OLAP               |
| ------------------ | ------------------ |
| Daily Transactions | Analytics          |
| Small Queries      | Large Queries      |
| Normalized         | Often Denormalized |
| Frequent Updates   | Mostly Reads       |
| Fast Writes        | Fast Reads         |

---

## Drawbacks

* OLTP is not optimized for reporting.
* OLAP is not suitable for frequent transactional updates.

---

## Quick Revision

* OLTP → Transactions
* OLAP → Analytics

# 47. MERGE (UPSERT)

## Definition

**MERGE (UPSERT)** inserts new rows if they do not exist or updates existing rows if they already exist.

---

## Why

During ETL, incoming data may contain both new and existing records.

Instead of writing separate INSERT and UPDATE statements, use one MERGE operation.

---

## Analogy

School Admission

* Student already exists → Update details.
* New student → Add new record.

---

## Syntax

```sql
MERGE INTO target t

USING source s

ON t.customer_id = s.customer_id

WHEN MATCHED THEN
UPDATE SET name = s.name

WHEN NOT MATCHED THEN
INSERT(customer_id,name)
VALUES(s.customer_id,s.name);
```

---

## Execution

```text
Incoming Data

↓

Exists?

↓

Yes → UPDATE

↓

No → INSERT
```

---

## Drawbacks

* Slightly slower than a simple INSERT for very small datasets.
* Syntax differs between databases.

---

## Quick Revision

* INSERT + UPDATE
* One Statement
* ETL Friendly

# 48. Incremental Loading

## Definition

**Incremental Loading** loads only new or changed records instead of loading the entire dataset every time.

---

## Why

Imagine a table with 100 million rows.

Reloading all rows every hour is inefficient.

Load only new changes.

---

## Analogy

Reading today's newspaper.

You don't re-read yesterday's newspaper every morning.

---

## Example

```sql
SELECT *

FROM orders

WHERE updated_at >

'2026-06-01 10:00:00';
```

Only records updated after the last successful load are fetched.

---

## Execution

```text
Last Load Time

↓

Find New Records

↓

Load Only Changes
```

---

## Drawbacks

* Requires reliable timestamps or change tracking.
* Missing timestamps can lead to missing data.

---

## Quick Revision

* Faster ETL
* Less Data Movement
* Production Standard

# 49. SCD Type 1

## Definition

**Slowly Changing Dimension (Type 1)** updates the existing record and does not preserve history.

---

## Why

Use when historical values are not important.

---

## Analogy

Changing your mobile number.

You replace the old number.

You don't keep all previous numbers.

---

## Example

Before

```text
Customer

ID | City
---+--------
1  | Mumbai
```

Update

```text
City → Pune
```

After

```text
Customer

ID | City
---+--------
1  | Pune
```

History is lost.

---

## Execution

```text
Existing Row

↓

UPDATE

↓

Old Value Replaced
```

---

## Drawbacks

* Historical information is permanently lost.

---

## Quick Revision

* UPDATE
* No History
* Simple

---

# 50. SCD Type 2

## Definition

**Slowly Changing Dimension (Type 2)** preserves history by creating a new row whenever a value changes.

---

## Why

Businesses often need to know **what the data looked like at a particular point in time**.

Examples:

* Customer address history
* Employee department history
* Product price history

---

## Analogy

Passport Renewal

Instead of overwriting the old passport,

a new passport is issued.

The old passport still exists for historical reference.

---

## Example

Before

```text
Customer

ID | City    | Start_Date | End_Date | Current
---+---------+------------+----------+--------
1  | Mumbai  | 2025-01-01 | NULL     | Yes
```

Customer moves to Pune.

After

```text
ID | City    | Start_Date | End_Date   | Current
---+---------+------------+------------+--------
1  | Mumbai  | 2025-01-01 | 2026-06-30 | No
1  | Pune    | 2026-07-01 | NULL       | Yes
```

---

## Execution

```text
Current Row

↓

Close Existing Record

↓

Insert New Record

↓

History Preserved
```

---

## Drawbacks

* More storage required.
* ETL logic becomes more complex.

---

## Quick Revision

* Keep History
* Insert New Row
* Warehouse Standard

---

# SCD Type 1 vs Type 2

| Feature           | Type 1 | Type 2       |
| ----------------- | ------ | ------------ |
| History Preserved | ❌ No   | ✅ Yes        |
| UPDATE            | ✅ Yes  | ❌ No         |
| INSERT New Row    | ❌ No   | ✅ Yes        |
| Storage           | Low    | Higher       |
| ETL Complexity    | Simple | More Complex |
