# 20. Subqueries

## Definition

A **Subquery** is a query written inside another SQL query.

---

## Why

Used when one query depends on the result of another query.

---

## Analogy

Imagine asking your manager:

> "Who is the employee with the highest salary?"

First,

Find highest salary.

Then,

Find employee having that salary.

One question inside another.

---

## Syntax

```sql
SELECT ...

FROM table

WHERE column = (

SELECT ...

);
```

---

## Fully Commented SQL

```sql
SELECT *

FROM orders                                       -- Outer Query

WHERE amount = (

    SELECT MAX(amount)                            -- Inner Query

    FROM orders

);
```

---

## Execution

```text
Step 1

SELECT MAX(amount)

↓

80000

---------------------

Step 2

SELECT *

WHERE amount=80000
```

---

## Drawbacks

* May execute repeatedly.
* Can become slower than JOIN or CTE.

---

## Quick Revision

* Query inside Query
* Used for dependent logic

---

# 21. CTE (Common Table Expression)

## Definition

A **CTE** creates a temporary named result set that can be reused within a query.

---

## Why

Improves readability.

Breaks large SQL into smaller pieces.

---

## Analogy

Instead of solving one huge maths problem,

solve Part A,

give it a name,

then use it later.

---

## Syntax

```sql
WITH name AS (

SELECT ...

)

SELECT *

FROM name;
```

---

## Fully Commented SQL

```sql
WITH HighOrders AS (                        -- Temporary Result

    SELECT *

    FROM orders

    WHERE amount > 10000

)

SELECT *

FROM HighOrders;
```

---

## Execution

```text
Orders

↓

Temporary Table (HighOrders)

↓

Final SELECT
```

---

## Drawbacks

* Exists only during query execution.
* Doesn't permanently store data.

---

## Quick Revision

* Temporary Table
* Better Readability
* One Query Only

---

# 22. Recursive CTE

## Definition

A **Recursive CTE** repeatedly calls itself until a stopping condition is reached.

---

## Why

Used for hierarchical data.

Example:

Employee → Manager

Category → Subcategory

Folder → Subfolder

---

## Analogy

Family Tree.

Parent

↓

Child

↓

Grandchild

↓

Great Grandchild

---

## Syntax

```sql
WITH RECURSIVE ...

UNION ALL

SELECT ...
```

---

## Example

```sql
WITH RECURSIVE Numbers AS (

    SELECT 1 AS n                     -- Starting Value

    UNION ALL

    SELECT n+1                        -- Recursive Part

    FROM Numbers

    WHERE n<5                         -- Stop Condition

)

SELECT *

FROM Numbers;
```

---

## Output

```text
1
2
3
4
5
```

---

## Drawbacks

Missing stop condition

↓

Infinite recursion.

---

## Quick Revision

* Hierarchy
* Tree Structure
* Self Calling Query

---

# 23. Window Functions

## Definition

A **Window Function** performs calculations across related rows without collapsing them into a single row.

---

## Why

Unlike GROUP BY,

all rows remain visible.

---

## Analogy

Class Rank.

Every student keeps their own marks,

but ranking is calculated across the whole class.

---

## Syntax

```sql
Function()

OVER(

PARTITION BY ...

ORDER BY ...

)
```

---

## Fully Commented SQL

```sql
SELECT

customer_id,

amount,

ROW_NUMBER() OVER(

PARTITION BY customer_id              -- Restart for each customer

ORDER BY amount DESC                  -- Highest Amount First

) AS rn

FROM orders;
```

---

## Execution

```text
Customer 1

80000 → Rank 1

15000 → Rank 2

1000 → Rank 3

-----------------

Customer 2

35000 → Rank 1

2500 → Rank 2
```

---

## Drawbacks

Can become expensive on very large datasets without indexes.

---

## Quick Revision

* Doesn't collapse rows
* Uses OVER()
* Supports Ranking
* Supports Running Totals

# 24. LEAD & LAG

## Definition

LEAD accesses the next row.

LAG accesses the previous row.

---

## Why

Useful for comparing current rows with previous or next values.

---

## Analogy

Standing in a queue.

Look ahead.

↓

LEAD

Look behind.

↓

LAG

---

## Syntax

```sql
LEAD(column)

OVER(...)

LAG(column)

OVER(...)
```

---

## Fully Commented SQL

```sql
SELECT

order_id,

amount,

LAG(amount) OVER(

ORDER BY order_date

) AS previous_amount,

LEAD(amount) OVER(

ORDER BY order_date

) AS next_amount

FROM orders;
```

---

## Execution

```text
1000

↓

Previous NULL

Next 2500

------------

2500

↓

Previous 1000

Next 15000
```

---

## Drawbacks

Needs ordering.

Wrong ORDER BY gives incorrect results.

---

## Quick Revision

LEAD

↓

Next Row

---

LAG

↓

Previous Row

---

# 25. Date Functions

## Definition

Date Functions manipulate and calculate dates and times.

---

## Why

Almost every business query uses dates.

Sales

Attendance

Orders

Invoices

Subscriptions

---

## Common Functions

```sql
CURRENT_DATE

CURRENT_TIMESTAMP

AGE()

DATE_PART()

EXTRACT()

NOW()
```

---

## Fully Commented SQL

```sql
SELECT

CURRENT_DATE,                    -- Today's Date

CURRENT_TIMESTAMP,               -- Current Date + Time

AGE(CURRENT_DATE,'2000-01-01'),  -- Difference

EXTRACT(YEAR FROM CURRENT_DATE); -- Extract Year
```

---

## Drawbacks

Different databases provide slightly different date functions.

---

## Quick Revision

CURRENT_DATE

↓

Today's Date

---

NOW()

↓

Current Timestamp

---

AGE()

↓

Difference

---

EXTRACT()

↓

Month

Year

Day

